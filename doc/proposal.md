## 2. 背景与目标

### 2.1 背景

本项目目标是建设一个现代化、高度可自定义的 SaaS Chatbot 平台。平台面向多行业客户，允许每个租户创建和管理多个独立 chatbot，并将 chatbot 部署到租户自己的网站或独立聊天页面中。

系统包含三类主要使用端：

1. 用户端 chatbot：面向最终访客，提供自动问答、大模型对话、知识库问答和后续人工客服能力。
2. 租户端：面向 SaaS 客户，用于配置机器人、知识库、外观、行为策略、部署渠道、成员权限、统计报表等。
3. 超级管理员端：面向平台运营方，用于管理租户、套餐额度、系统模型配置、运营监控和审计。

### 2.2 产品目标

1. 支持多租户 SaaS 模式，每个租户数据严格隔离。
2. 支持每个租户创建多个 chatbot。
3. 支持 chatbot 通过网站插件和独立聊天页对外提供服务。
4. MVP 优先实现 AI 自动服务能力：规则问答、知识库问答、大模型对话。
5. 人工客服能力作为二期重点建设，包含实时聊天、排队分配、工单沉淀和质检统计。
6. 支持套餐额度限制，包括机器人数量、消息量、知识库容量、Token 用量等。
7. 支持中英双语界面和中英双语问答能力。

### 2.3 非目标

MVP 阶段不包含以下内容：

1. 在线支付、自动续费和发票系统。
2. 移动 App。
3. 企业 SSO 登录。
4. API 同步外部知识库。
5. 完整人工坐席工作台。人工坐席在二期实现。

## 3. 用户角色

### 3.1 最终访客

最终访客通过网站插件或独立聊天页访问 chatbot。MVP 阶段最终访客采用匿名访问，不要求登录。

主要能力：

1. 发起对话。
2. 查看机器人回复。
3. 在机器人无法解决时留下问题和联系方式。
4. 后续阶段可请求转人工客服。

### 3.2 租户管理员

租户管理员管理当前租户下的所有资源。

主要能力：

1. 管理租户成员和角色。
2. 创建、编辑、删除 chatbot。
3. 配置知识库、规则问答和大模型参数。
4. 配置 chatbot 外观、行为策略和部署渠道。
5. 查看会话记录、统计报表和额度使用情况。

### 3.3 机器人编辑

机器人编辑负责维护 chatbot 的内容和配置。

主要能力：

1. 编辑 chatbot 基础信息。
2. 配置外观样式。
3. 维护 FAQ、文件知识库和网页知识。
4. 配置提示词、回复风格、兜底话术和敏感词策略。
5. 查看与机器人相关的测试结果。

### 3.4 客服坐席

客服坐席负责处理转人工后的会话。MVP 阶段可预留角色和权限，二期实现完整工作台。

主要能力：

1. 查看分配给自己的会话。
2. 实时回复访客。
3. 结束会话并填写处理结果。
4. 将会话沉淀为工单或跟进记录。

### 3.5 数据分析员

数据分析员负责查看统计报表和会话数据。

主要能力：

1. 查看消息量、会话量和活跃访客。
2. 查看 AI 命中率、未解决率、转人工率。
3. 查看 Token 用量、模型调用成本和套餐额度消耗。
4. 导出授权范围内的数据。

### 3.6 超级管理员

超级管理员负责整个平台的运营管理。

主要能力：

1. 管理租户、租户管理员和租户状态。
2. 管理套餐、额度和租户用量限制。
3. 配置大模型供应商和全局系统参数。
4. 查看平台级运营监控、异常告警和审计日志。

## 4. 系统范围与阶段规划

### 4.1 MVP 范围

MVP 聚焦 AI 自动服务能力，包含：

1. 多租户基础能力。
2. 超级管理员端基础管理。
3. 租户端机器人管理。
4. 网站插件和独立聊天页。
5. 匿名访客对话。
6. 规则问答。
7. 知识库问答。
8. 大模型对话。
9. 多模型供应商配置。
10. FAQ 手工录入、文件上传、网页抓取。
11. 会话记录、隐私脱敏、数据隔离、数据导出和删除。
12. 套餐额度限制。
13. 中英双语界面和问答能力。

### 4.2 二期范围

二期重点建设实时人工客服能力，包含：

1. 实时坐席工作台。
2. 访客转人工。
3. 坐席在线状态。
4. 排队和会话分配。
5. 工单沉淀。
6. 坐席效率统计。
7. 满意度评价。
8. 会话质检统计。

### 4.3 长期范围

长期可扩展能力包含：

1. 在线支付和订阅续费。
2. 企业 SSO。
3. 多渠道接入，如 WhatsApp、微信、Slack、邮件等。
4. API 同步外部知识。
5. 更完整的多语言后台和多语言知识库。
6. 多区域部署和高可用架构。

## 5. 功能需求

## 5.1 用户端 Chatbot

### 5.1.1 部署入口

系统必须支持两类用户端入口：

1. 网站插件：租户复制一段 JavaScript 脚本嵌入自己的网站。
2. 独立聊天页：每个 chatbot 拥有一个独立 URL，可直接分享给访客。

验收标准：

1. 租户可以在后台获取插件脚本。
2. 插件脚本加载后，在租户配置允许的域名中展示聊天窗口。
3. 独立聊天页可以通过公开链接访问。
4. 两类入口都必须使用同一套 chatbot 配置。

### 5.1.2 匿名会话

MVP 阶段访客匿名访问 chatbot。

功能要求：

1. 访客无需登录即可开始对话。
2. 系统为每个访客生成匿名访客 ID。
3. 系统记录会话 ID、访客 ID、来源入口、浏览器信息、IP 地址和时间。
4. 租户后台展示访客信息时必须遵守隐私脱敏策略。

### 5.1.3 对话体验

功能要求：

1. 支持中英文输入。
2. 支持连续对话。
3. 支持展示机器人正在输入状态。
4. 支持错误提示和兜底话术。
5. 支持展示引用的知识来源。
6. 支持访客复制回答内容。
7. 支持访客反馈回答是否有帮助。

### 5.1.4 转人工入口

MVP 阶段预留转人工入口，但不实现完整实时坐席。

MVP 功能要求：

1. 当机器人无法回答时，引导访客留下问题和联系方式。
2. 系统将该记录保存为待跟进记录。

二期功能要求：

1. 访客可点击转人工按钮进入人工排队。
2. 坐席接入后，访客可与坐席实时聊天。

## 5.2 租户端

### 5.2.1 登录认证

租户端采用邮箱密码登录。

功能要求：

1. 支持邮箱和密码登录。
2. 支持退出登录。
3. 支持忘记密码和重置密码。
4. 密码必须加密存储。
5. 登录失败需要有频率限制。

### 5.2.2 租户工作台

租户登录后进入工作台。

工作台展示：

1. 当前套餐信息。
2. 已创建 chatbot 数量和套餐上限。
3. 当月消息量和套餐上限。
4. Token 用量和成本估算。
5. 最近会话。
6. AI 未解决问题列表。
7. 系统通知。

### 5.2.3 Chatbot 管理

功能要求：

1. 创建 chatbot。
2. 编辑 chatbot 名称、描述、语言、状态。
3. 启用或停用 chatbot。
4. 删除 chatbot。
5. 复制 chatbot 配置。
6. 查看 chatbot 的部署代码和独立聊天页链接。

约束：

1. 每个 chatbot 必须属于一个租户。
2. 创建数量受套餐限制。
3. 停用后，用户端不能继续发起新会话。

### 5.2.4 外观样式配置

租户可配置 chatbot 的视觉表现。

配置项：

1. 机器人名称。
2. 机器人头像。
3. 欢迎语。
4. 主题颜色。
5. 聊天气泡位置。
6. 启动按钮样式。
7. 品牌标识显示策略。
8. 中英文界面文案。

验收标准：

1. 配置保存后，网站插件和独立聊天页同时生效。
2. 租户可在后台预览配置效果。

### 5.2.5 行为策略配置

行为策略用于控制机器人如何回答。

配置项：

1. 回复语言。
2. 回复风格。
3. 系统提示词。
4. 兜底话术。
5. 敏感词策略。
6. 是否展示知识引用来源。
7. 是否允许访客反馈。
8. 是否启用转人工引导。
9. 模型温度、最大回复长度等模型参数。

### 5.2.6 规则问答

规则问答用于处理明确、高频、结构化问题。

功能要求：

1. 支持 FAQ 手工录入。
2. 每条 FAQ 包含问题、相似问法、答案、语言、状态和所属 chatbot。
3. 支持批量导入和导出 FAQ。
4. 支持启用、停用、删除 FAQ。
5. 支持按关键词搜索 FAQ。

匹配要求：

1. 系统优先匹配启用状态的规则问答。
2. 命中规则问答时，可直接返回规则答案。
3. 未命中时进入知识库问答或大模型对话流程。

### 5.2.7 知识库管理

MVP 支持三类知识来源：

1. FAQ 手工录入。
2. 文件上传。
3. 网页抓取。

#### 文件上传

支持文件类型：

1. PDF。
2. Word。
3. TXT。
4. Markdown。

功能要求：

1. 租户上传文件后，系统解析文本内容。
2. 系统将文本切分为知识片段。
3. 系统为知识片段生成向量并存入 pgvector。
4. 系统记录文件解析状态。
5. 解析失败时展示失败原因。

#### 网页抓取

功能要求：

1. 租户输入 URL。
2. 系统抓取网页正文。
3. 系统支持重新抓取。
4. 系统记录抓取时间、抓取状态和来源 URL。

限制：

1. 仅抓取租户有权使用的公开网页。
2. 抓取频率需要限制。
3. 抓取结果必须归属到当前租户。

### 5.2.8 大模型配置

平台支持多模型供应商，由超级管理员配置可用供应商，租户在允许范围内选择使用。

功能要求：

1. 支持多个模型供应商。
2. 支持配置模型名称、API 地址、密钥、默认参数和启用状态。
3. 支持按租户或套餐限制可用模型。
4. 支持记录每次模型调用的 Token 用量和成本估算。
5. 支持失败重试和错误记录。

### 5.2.9 渠道部署

功能要求：

1. 生成网站插件嵌入代码。
2. 管理允许嵌入的域名白名单。
3. 生成独立聊天页链接。
4. 支持复制部署代码。
5. 展示最近部署访问情况。

安全要求：

1. 插件请求必须携带 chatbot 标识。
2. 后端必须校验 chatbot 状态和域名白名单。
3. 禁止跨租户访问 chatbot 配置。

### 5.2.10 会话记录

功能要求：

1. 查看会话列表。
2. 查看会话详情。
3. 查看访客问题、机器人回答、命中的 FAQ、引用的知识片段和模型调用信息。
4. 标记会话是否已解决。
5. 查看访客反馈。
6. 导出会话数据。
7. 删除会话数据。

隐私要求：

1. 邮箱、手机号、IP 等敏感信息默认脱敏展示。
2. 只有授权角色可以查看完整敏感信息。
3. 删除数据必须仅影响当前租户。

### 5.2.11 统计报表

租户端统计指标包含：

1. 会话数。
2. 消息数。
3. 活跃访客数。
4. 规则问答命中率。
5. 知识库命中率。
6. 未解决率。
7. 转人工率。
8. Token 用量。
9. 模型调用成本估算。
10. 套餐额度消耗。

二期增加坐席指标：

1. 坐席接待量。
2. 首次响应时长。
3. 平均处理时长。
4. 排队时长。
5. 满意度。
6. 质检结果。

### 5.2.12 成员与权限

租户端角色包含：

1. 租户管理员。
2. 机器人编辑。
3. 客服坐席。

权限矩阵：

## 6. 核心业务流程

### 6.1 机器人自动回答流程

1. 访客发送消息。
2. 系统校验 chatbot 状态、租户状态和套餐额度。
3. 系统记录访客消息。
4. 系统尝试匹配规则问答。
5. 如果规则问答命中，返回规则答案。
6. 如果规则问答未命中，执行知识库检索。
7. 如果知识库检索命中，将相关片段作为上下文调用大模型。
8. 如果知识库检索未命中，根据行为策略决定是否调用大模型直接回答。
9. 系统记录模型调用、Token 用量、引用来源和回答内容。
10. 系统返回机器人回答。

### 6.2 租户创建 chatbot 流程

1. 租户管理员点击创建 chatbot。
2. 系统检查套餐机器人数量上限。
3. 租户填写名称、语言、欢迎语和基础配置。
4. 系统创建 chatbot。
5. 租户配置外观、知识库和行为策略。
6. 租户获取插件代码或独立聊天页链接。

### 6.3 知识库文件处理流程

1. 租户上传文件。
2. 系统保存原始文件到本地存储。
3. 系统创建解析任务。
4. 系统解析文本。
5. 系统切分文本。
6. 系统生成向量。
7. 系统保存知识片段和向量到 PostgreSQL/pgvector。
8. 系统更新文件状态。

### 6.4 套餐额度校验流程

1. 用户或租户触发消耗额度的操作。
2. 系统读取租户套餐和自定义额度。
3. 系统检查机器人数量、消息量、知识库容量、文件数量和 Token 用量。
4. 如果超出额度，系统拒绝操作并展示原因。
5. 如果未超出额度，系统允许操作并记录消耗。

## 7. 数据需求

### 7.1 核心实体

系统至少包含以下核心实体：

1. Tenant：租户。
2. User：后台用户。
3. Role：角色。
4. Permission：权限。
5. Chatbot：机器人。
6. ChatbotAppearance：机器人外观配置。
7. ChatbotBehavior：机器人行为配置。
8. FAQ：规则问答。
9. KnowledgeSource：知识来源。
10. KnowledgeChunk：知识片段。
11. Conversation：会话。
12. Message：消息。
13. ModelProvider：模型供应商。
14. ModelCallLog：模型调用日志。
15. Plan：套餐。
16. TenantQuota：租户额度。
17. UsageRecord：用量记录。
18. AuditLog：审计日志。
19. HandoffRecord：MVP 阶段的转人工跟进记录。
20. AgentSession：二期人工坐席会话。
21. Ticket：二期工单。

### 7.2 多租户数据隔离

要求：

1. 所有租户业务数据必须包含 tenant_id。
2. 后端所有租户级查询必须按 tenant_id 过滤。
3. 不允许客户端直接传入 tenant_id 后绕过权限访问其他租户数据。
4. 超级管理员访问租户数据必须记录审计日志。

### 7.3 数据保留与删除

要求：

1. 租户可导出会话数据。
2. 租户可删除会话数据。
3. 删除操作必须记录审计日志。
4. 后续可支持数据保留周期配置。

## 8. 非功能需求

### 8.1 安全

1. 密码必须使用安全哈希算法存储。
2. 后台接口必须鉴权。
3. 租户数据必须严格隔离。
4. 插件入口必须校验 chatbot 状态和域名白名单。
5. API 密钥必须加密保存或使用安全配置管理。
6. 敏感信息默认脱敏展示。
7. 文件上传必须限制类型和大小。
8. 网页抓取必须限制频率和超时时间。

### 8.2 性能

MVP 建议指标：

1. 聊天接口普通响应在 3 秒内返回首个结果或处理中状态。
2. 规则问答匹配在 500 毫秒内完成。
3. 知识库检索在 1 秒内完成。
4. 后台列表页在 2 秒内返回。
5. 文件解析允许异步处理。

### 8.3 可用性

1. 模型供应商调用失败时应返回友好错误或兜底话术。
2. 文件解析失败时应展示明确原因。
3. 套餐额度不足时应展示具体限制项。
4. 系统关键操作需要审计。

### 8.4 国际化

1. 用户端 chatbot 支持中文和英文界面。
2. 租户端和超级管理员端支持中文和英文界面。
3. 知识库和 FAQ 支持中文和英文内容。
4. chatbot 可按配置选择默认回复语言。

## 9. 技术规格

### 9.1 前端

技术栈：React SPA。

建议组成：

1. React。
2. TypeScript。
3. Vite。
4. React Router。
5. 状态管理可使用 Zustand 或 Redux Toolkit。
6. UI 组件库可使用 Ant Design 或 Material UI。

前端应用拆分：

1. tenant-admin：租户端后台。
2. super-admin：超级管理员后台。
3. chatbot-widget：网站插件。
4. chat-page：独立聊天页。

### 9.2 后端

技术栈：Java Spring Boot。

建议组成：

1. Spring Boot。
2. Spring Security。
3. Spring Data JPA 或 MyBatis。
4. PostgreSQL JDBC。
5. WebSocket 或 SSE，用于后续实时聊天和流式回复。
6. 异步任务处理，用于文件解析、网页抓取和向量生成。

### 9.3 数据库与向量检索

技术栈：PostgreSQL + pgvector。

用途：

1. PostgreSQL 存储业务关系数据。
2. pgvector 存储知识片段向量。
3. 使用 tenant_id 和 chatbot_id 过滤检索范围。

### 9.4 文件存储

MVP 使用本地存储。

要求：

1. 文件路径必须与租户隔离。
2. 禁止通过公开路径直接访问原始文件。
3. 需要记录文件元数据、大小、类型、上传人和解析状态。
4. 后续可迁移到 S3 兼容对象存储。

### 9.5 部署

MVP 使用 Docker 单机部署。

建议服务：

1. frontend：前端静态资源服务。
2. backend：Spring Boot API 服务。
3. postgres：PostgreSQL + pgvector。
4. reverse-proxy：Nginx 或 Caddy。

## 11. 验收标准

### 11.1 MVP 总体验收

1. 超级管理员可以创建租户并分配套餐。
2. 租户管理员可以登录租户端。
3. 租户管理员可以创建 chatbot。
4. 租户可以配置 chatbot 外观、规则问答、知识库和行为策略。
5. 租户可以获取网站插件代码和独立聊天页链接。
6. 访客可以匿名发起对话。
7. 系统可以完成规则问答回复。
8. 系统可以基于文件或网页知识库回答问题。
9. 系统可以调用配置的大模型生成回答。
10. 系统可以记录会话、消息、Token 用量和知识引用。
11. 租户只能查看自己的数据。
12. 超出套餐额度时，系统能阻止对应操作。
13. 敏感信息默认脱敏。
14. 租户可以导出和删除授权范围内的会话数据。
15. 中英文界面和问答可用。

### 11.2 二期验收

1. 访客可以请求转人工。
2. 坐席可以设置在线状态。
3. 系统可以排队和分配会话。
4. 坐席可以实时回复访客。
5. 会话可以沉淀为工单。
6. 系统可以统计坐席效率和满意度。

## 12. 风险与待确认事项

### 12.1 风险

1. 大模型回复质量依赖知识库质量和提示词设计。
2. 网页抓取存在授权、结构变化和反爬限制风险。
3. 本地文件存储适合 MVP，但生产规模扩大后需要迁移到对象存储。
4. Docker 单机部署适合 MVP，但高并发和高可用场景需要进一步架构升级。
5. 多模型供应商成本和稳定性需要持续监控。

### 12.2 待确认事项

以下事项未在当前需求确认中确定，后续进入详细设计前需要继续确认：

1. 具体支持哪些模型供应商。
2. 每个套餐的具体额度数值。
3. 文件上传大小限制。
4. 网页抓取深度和频率限制。
5. 会话数据默认保留周期。
6. 是否需要流式输出。
7. 是否需要对回答进行内容安全审核。
8. 是否需要租户自定义域名访问独立聊天页。
