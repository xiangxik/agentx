# SaaS 多租户 Chatbot 系统概要设计文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档名称 | SaaS 多租户 Chatbot 系统概要设计文档 |
| 输入文档 | `doc/proposal.md` |

## 2. 设计目标与原则

### 2.1 设计目标

1. 支撑多租户 SaaS 模式，确保租户数据隔离。
2. 支撑每个租户创建和管理多个 chatbot。
3. 支撑网站插件和独立聊天页两类访客入口。
4. 支撑 MVP 阶段 AI 自动服务能力：规则问答、知识库问答、大模型对话。
5. 支撑套餐额度、用量统计、审计日志、隐私脱敏和数据导出删除。
6. 为二期实时人工客服、排队分配、工单和质检统计预留模块边界。

### 2.2 设计原则

1. **租户隔离优先**：所有租户业务数据以 `tenant_id` 作为隔离边界，后端基于认证上下文确定租户范围。
2. **模块职责清晰**：按用户端、租户端、超级管理员端和公共基础能力划分模块。
3. **MVP 优先**：优先覆盖自动服务闭环；二期能力仅保留角色、实体和接口边界。
4. **配置统一复用**：网站插件和独立聊天页使用同一套 chatbot 配置。
5. **异步处理耗时任务**：文件解析、网页抓取和向量生成通过异步任务处理。

## 3. 总体架构

### 3.1 逻辑架构

系统由以下层次组成：

1. **访问层**
   - 租户端后台：面向租户管理员、机器人编辑、客服坐席、数据分析员。
   - 超级管理员后台：面向平台运营方。
   - Chatbot 网站插件：嵌入租户网站的访客聊天入口。
   - 独立聊天页：可公开访问的 chatbot 独立 URL。

2. **API 与应用服务层**
   - 认证与权限服务。
   - 租户、用户、角色、权限服务。
   - Chatbot 配置服务。
   - 知识库与规则问答服务。
   - 对话编排服务。
   - 模型供应商与模型调用服务。
   - 套餐额度与用量服务。
   - 会话记录、统计报表、审计服务。
   - 二期人工客服、工单服务边界。

3. **异步任务层**
   - 文件解析任务。
   - 网页抓取任务。
   - 文本切分与向量生成任务。

4. **数据与存储层**
   - PostgreSQL：存储租户、用户、chatbot、会话、消息、套餐、审计等关系数据。
   - pgvector：存储知识片段向量并支持相似度检索。
   - 本地文件存储：保存 MVP 阶段上传的原始文件。

5. **外部依赖层**
   - 大模型供应商 API。
   - 网页抓取目标站点。

### 3.2 部署架构

MVP 使用 Docker 单机部署，建议服务如下：

1. `frontend`：托管租户端后台、超级管理员后台、网站插件和独立聊天页静态资源。
2. `backend`：Spring Boot API 服务，承载同步接口、对话编排和异步任务调度。
3. `postgres`：PostgreSQL + pgvector。
4. `reverse-proxy`：Nginx 或 Caddy，负责入口路由和静态资源/API 转发。

## 4. 前端应用划分

| 应用 | 使用者 | 主要职责 | 依赖后端模块 |
| --- | --- | --- | --- |
| `tenant-admin` | 租户管理员、机器人编辑、客服坐席、数据分析员 | 租户工作台、chatbot 管理、知识库、会话、统计、成员权限、额度查看 | Auth、User、Chatbot、Knowledge、Conversation、Analytics、Plan |
| `super-admin` | 超级管理员 | 租户管理、套餐额度、模型供应商、运营监控、审计日志 | Auth、Tenant、Plan、Model Provider、Analytics、Audit |
| `chatbot-widget` | 最终访客 | 嵌入网站的聊天窗口，匿名会话、消息收发、反馈、转人工入口预留 | Chat、Chatbot 配置、Conversation |
| `chat-page` | 最终访客 | 独立 URL 聊天页面，复用 chatbot 配置和对话能力 | Chat、Chatbot 配置、Conversation |

## 5. 后端模块划分

### 5.1 认证与权限模块

**对应 API**：Auth API、User API。

**职责**：

1. 租户端和超级管理员端邮箱密码登录、退出、密码重置。
2. 密码安全哈希存储。
3. 登录失败频率限制。
4. 后台接口鉴权。
5. 租户成员、角色、权限管理。
6. 基于角色控制后台功能访问范围。

**核心实体**：`User`、`Role`、`Permission`、`Tenant`。

**依赖关系**：

- 被租户端后台、超级管理员后台和所有后台业务 API 依赖。
- 为租户数据隔离提供认证上下文。
- 与审计模块协作记录登录、退出和关键权限操作。

### 5.2 租户管理模块

**对应 API**：Tenant API。

**职责**：

1. 超级管理员创建、编辑、启用、禁用租户。
2. 创建租户管理员账号。
3. 查看租户用量、chatbot 数量和异常情况。
4. 维护租户状态，参与 chatbot 对话前置校验。

**核心实体**：`Tenant`、`User`。

**依赖关系**：

- 依赖套餐额度模块获取租户套餐和额度。
- 被 Chatbot 管理、对话编排、统计报表和审计模块依赖。

### 5.3 套餐额度与用量模块

**对应 API**：Plan API。

**职责**：

1. 超级管理员创建和维护套餐。
2. 配置机器人数量、月消息量、知识库容量、文件数量、Token 用量、可用模型范围。
3. 为租户分配套餐并支持租户级额度调整。
4. 在创建 chatbot、发送消息、上传文件、生成向量、调用模型等操作前执行额度校验。
5. 记录用量消耗。

**核心实体**：`Plan`、`TenantQuota`、`UsageRecord`。

**依赖关系**：

- 被 Chatbot 管理、知识库管理、对话编排、模型调用模块依赖。
- 向租户工作台、统计报表和超级管理员运营监控提供用量数据。

### 5.4 Chatbot 管理模块

**对应 API**：Chatbot API、Appearance API、Behavior API。

**职责**：

1. 创建、编辑、启用、停用、删除、复制 chatbot。
2. 管理 chatbot 名称、描述、语言、状态。
3. 管理外观配置：头像、欢迎语、主题色、气泡位置、启动按钮样式、品牌标识、中英文文案。
4. 管理行为策略：回复语言、回复风格、系统提示词、兜底话术、敏感词策略、引用来源、访客反馈、转人工引导、模型参数。
5. 生成网站插件代码和独立聊天页链接所需的 chatbot 标识。

**核心实体**：`Chatbot`、`ChatbotAppearance`、`ChatbotBehavior`。

**依赖关系**：

- 依赖租户管理模块确定归属租户。
- 依赖套餐额度模块校验机器人数量上限。
- 被渠道部署、用户端 Chat、规则问答、知识库、会话记录和统计报表模块依赖。

### 5.5 渠道部署模块

**对应 API**：Chatbot API 中的部署能力或独立 Deployment API。

**职责**：

1. 生成网站插件嵌入代码。
2. 管理允许嵌入域名白名单。
3. 生成独立聊天页链接。
4. 展示最近部署访问情况。
5. 校验插件请求中的 chatbot 标识、chatbot 状态和域名白名单。

**核心实体**：`Chatbot` 及其部署配置。

**依赖关系**：

- 依赖 Chatbot 管理模块读取配置和状态。
- 被 `chatbot-widget` 和 `chat-page` 访问。
- 与租户隔离规则共同防止跨租户访问 chatbot 配置。

### 5.6 规则问答模块

**对应 API**：FAQ API。

**职责**：

1. FAQ 手工录入、批量导入、导出。
2. FAQ 启用、停用、删除和关键词搜索。
3. 维护问题、相似问法、答案、语言、状态、所属 chatbot。
4. 在机器人自动回答流程中优先执行规则匹配。

**核心实体**：`FAQ`。

**依赖关系**：

- 依赖 Chatbot 管理模块确定 FAQ 所属 chatbot。
- 被对话编排模块优先调用。
- 向会话记录模块输出命中的 FAQ 信息。

### 5.7 知识库模块

**对应 API**：Knowledge API。

**职责**：

1. 管理知识来源：FAQ 手工录入、文件上传、网页抓取。
2. 文件上传、类型限制、大小限制、元数据记录和解析状态记录。
3. 网页 URL 录入、抓取、重新抓取、频率限制、状态记录。
4. 文本解析、切分、向量生成和 pgvector 入库。
5. 按 `tenant_id` 和 `chatbot_id` 限定知识检索范围。
6. 解析或抓取失败时记录并展示失败原因。

**核心实体**：`KnowledgeSource`、`KnowledgeChunk`。

**依赖关系**：

- 依赖 Chatbot 管理模块确定知识归属。
- 依赖套餐额度模块校验知识库容量和文件数量。
- 依赖模型调用模块生成向量。
- 被对话编排模块检索调用。
- 依赖本地文件存储保存原始文件。

### 5.8 对话编排模块

**对应 API**：Chat API。

**职责**：

1. 支持匿名访客会话。
2. 生成匿名访客 ID。
3. 记录会话 ID、访客 ID、来源入口、浏览器信息、IP 地址和时间。
4. 接收访客消息并编排自动回答流程。
5. 返回规则问答、知识库增强回答或大模型直接回答。
6. 返回机器人正在输入状态、错误提示、兜底话术、引用来源和反馈入口所需数据。
7. 当无法回答时创建待跟进记录。

**核心实体**：`Conversation`、`Message`、`HandoffRecord`、`ModelCallLog`。

**依赖关系**：

- 依赖渠道部署模块校验入口合法性。
- 依赖租户管理和 Chatbot 管理模块校验租户、chatbot 状态。
- 依赖套餐额度模块校验消息量和 Token 用量。
- 依赖规则问答模块优先匹配 FAQ。
- 依赖知识库模块检索知识片段。
- 依赖模型调用模块生成回答。
- 向会话记录、统计报表和用量模块写入数据。

### 5.9 模型供应商与模型调用模块

**对应 API**：Model Provider API。

**职责**：

1. 超级管理员管理模型供应商、API 地址、密钥、模型列表、默认参数和启用状态。
2. 管理默认模型、全局调用超时时间和成本单价。
3. 支持按租户或套餐限制可用模型。
4. 为对话回答和知识向量生成提供模型调用能力。
5. 记录每次模型调用的 Token 用量、成本估算、失败重试和错误信息。
6. 提供模型调用失败率给运营监控。

**核心实体**：`ModelProvider`、`ModelCallLog`。

**依赖关系**：

- 依赖套餐额度模块判断可用模型范围和 Token 上限。
- 被知识库模块和对话编排模块调用。
- 向统计报表、运营监控和用量模块提供调用数据。

### 5.10 会话记录与数据管理模块

**对应 API**：Conversation API。

**职责**：

1. 查看会话列表和详情。
2. 查看访客问题、机器人回答、命中的 FAQ、引用知识片段、模型调用信息。
3. 标记会话是否已解决。
4. 查看访客反馈。
5. 导出和删除会话数据。
6. 对邮箱、手机号、IP 等敏感信息默认脱敏展示。
7. 控制授权角色查看完整敏感信息。

**核心实体**：`Conversation`、`Message`、`ModelCallLog`、`AuditLog`。

**依赖关系**：

- 由对话编排模块写入数据。
- 依赖认证与权限模块控制访问范围。
- 删除和导出操作依赖审计模块记录操作日志。
- 向统计报表模块提供指标数据。

### 5.11 统计报表模块

**对应 API**：Analytics API。

**职责**：

1. 租户端统计会话数、消息数、活跃访客数。
2. 统计规则问答命中率、知识库命中率、未解决率、转人工率。
3. 统计 Token 用量、模型调用成本估算和套餐额度消耗。
4. 超级管理员查看平台级租户数、活跃租户数、chatbot 总数、消息量、会话量、模型调用次数、Token 总用量、成本估算、错误率、慢请求数量。
5. 为二期坐席指标预留统计边界。

**核心实体**：`Conversation`、`Message`、`UsageRecord`、`ModelCallLog`、`Tenant`、`Chatbot`。

**依赖关系**：

- 读取会话记录、用量、模型调用、租户和 chatbot 数据。
- 依赖认证与权限模块区分租户级和平台级统计范围。

### 5.12 审计日志模块

**对应 API**：Audit API。

**职责**：

1. 记录登录和退出。
2. 记录创建、编辑、删除租户。
3. 记录修改套餐额度。
4. 记录修改模型供应商配置。
5. 记录禁用或启用租户。
6. 记录导出数据和删除数据。
7. 记录超级管理员访问租户数据的操作。

**核心实体**：`AuditLog`。

**依赖关系**：

- 被认证、租户管理、套餐额度、模型供应商、会话数据管理等模块调用。
- 向超级管理员后台提供审计查询能力。

### 5.13 二期人工客服模块

**对应 API**：Agent API。

**MVP 处理方式**：MVP 预留角色、权限、转人工入口和 `HandoffRecord`，不实现完整实时坐席工作台。

**二期职责**：

1. 访客请求转人工。
2. 坐席设置在线、忙碌、离线状态。
3. 系统自动分配或管理员手动分配会话。
4. 访客与坐席实时聊天。
5. 坐席结束会话并填写处理结果。

**核心实体**：`HandoffRecord`、`AgentSession`、`Message`。

**依赖关系**：

- 依赖对话编排模块提供转人工入口。
- 依赖认证与权限模块识别客服坐席。
- 向会话记录和二期统计报表写入人工服务数据。

### 5.14 二期工单模块

**对应 API**：Ticket API。

**MVP 处理方式**：不实现完整工单能力。

**二期职责**：

1. 将人工会话沉淀为工单。
2. 维护访客信息、问题摘要、处理状态、负责人和备注。
3. 支持工单状态流转。

**核心实体**：`Ticket`。

**依赖关系**：

- 依赖人工客服模块产生可沉淀的人工会话。
- 依赖认证与权限模块控制工单访问范围。

## 6. 核心业务流程设计

### 6.1 机器人自动回答流程

1. 访客通过网站插件或独立聊天页发送消息。
2. 渠道部署模块校验入口、chatbot 标识和域名白名单。
3. 对话编排模块校验 chatbot 状态、租户状态和套餐额度。
4. 对话编排模块记录访客消息。
5. 规则问答模块匹配启用状态 FAQ。
6. FAQ 命中时，对话编排模块直接返回规则答案并记录命中信息。
7. FAQ 未命中时，知识库模块按 `tenant_id` 和 `chatbot_id` 检索知识片段。
8. 知识片段命中时，模型调用模块结合片段上下文生成回答。
9. 知识片段未命中时，对话编排模块根据行为策略决定是否调用大模型直接回答。
10. 模型调用模块记录 Token 用量、成本估算、调用状态和错误信息。
11. 对话编排模块记录机器人回答、引用来源和反馈入口数据。
12. 对话编排模块返回回答；无法回答时按策略创建待跟进记录。

### 6.2 租户创建 chatbot 流程

1. 租户管理员发起创建 chatbot。
2. Chatbot 管理模块调用套餐额度模块检查机器人数量上限。
3. 租户管理员填写名称、语言、欢迎语和基础配置。
4. Chatbot 管理模块创建 chatbot、外观配置和行为配置。
5. 租户继续维护外观、知识库、FAQ 和行为策略。
6. 渠道部署模块生成网站插件代码和独立聊天页链接。

### 6.3 知识库文件处理流程

1. 租户上传文件。
2. 知识库模块校验文件类型、大小、租户权限和套餐额度。
3. 知识库模块将原始文件保存到租户隔离的本地存储路径。
4. 知识库模块创建解析任务并记录文件解析状态。
5. 异步任务解析文本内容。
6. 异步任务切分文本为知识片段。
7. 模型调用模块生成知识片段向量。
8. 知识库模块保存知识片段和向量到 PostgreSQL/pgvector。
9. 知识库模块更新文件状态；失败时记录失败原因。

### 6.4 套餐额度校验流程

1. 用户、租户或访客触发消耗额度的操作。
2. 套餐额度模块读取租户套餐和租户级自定义额度。
3. 套餐额度模块检查机器人数量、消息量、知识库容量、文件数量和 Token 用量。
4. 超出额度时拒绝操作并返回具体限制项。
5. 未超出额度时允许操作。
6. 操作完成后，用量模块记录消耗。

### 6.5 数据导出与删除流程

1. 授权后台用户发起会话数据导出或删除。
2. 认证与权限模块校验角色权限。
3. 会话记录模块按当前租户范围筛选数据。
4. 导出时生成授权范围内的数据结果。
5. 删除时仅删除当前租户范围内的数据。
6. 审计日志模块记录导出或删除操作。

## 7. 核心数据设计概览

### 7.1 实体分组

| 分组 | 实体 | 说明 |
| --- | --- | --- |
| 租户与权限 | `Tenant`、`User`、`Role`、`Permission` | 租户、后台用户和权限控制 |
| Chatbot 配置 | `Chatbot`、`ChatbotAppearance`、`ChatbotBehavior` | chatbot 基础信息、外观和行为策略 |
| 知识与规则 | `FAQ`、`KnowledgeSource`、`KnowledgeChunk` | 规则问答、文件/网页来源、知识片段和向量 |
| 对话与消息 | `Conversation`、`Message`、`HandoffRecord` | 匿名访客会话、消息、MVP 待跟进记录 |
| 模型调用 | `ModelProvider`、`ModelCallLog` | 模型供应商和调用日志 |
| 套餐用量 | `Plan`、`TenantQuota`、`UsageRecord` | 套餐、租户额度和消耗记录 |
| 审计 | `AuditLog` | 关键操作审计 |
| 二期客服 | `AgentSession`、`Ticket` | 人工坐席会话和工单 |

### 7.2 关键关系

1. 一个 `Tenant` 拥有多个 `User`、`Chatbot`、`UsageRecord`。
2. 一个 `Tenant` 分配一个 `Plan`，并可拥有租户级 `TenantQuota` 覆盖或补充额度。
3. 一个 `Chatbot` 拥有一份 `ChatbotAppearance` 和一份 `ChatbotBehavior`。
4. 一个 `Chatbot` 拥有多个 `FAQ`、`KnowledgeSource`、`Conversation`。
5. 一个 `KnowledgeSource` 拥有多个 `KnowledgeChunk`。
6. 一个 `Conversation` 拥有多条 `Message`。
7. 一次模型调用产生一条 `ModelCallLog`，可关联会话、消息或知识向量任务。
8. `AuditLog` 记录后台用户对租户、套餐、模型配置、数据导出删除等关键资源的操作。
9. 二期 `AgentSession` 可关联 `Conversation`，`Ticket` 可由人工会话沉淀生成。

### 7.3 租户隔离策略

1. 所有租户业务数据必须包含 `tenant_id`。
2. 后端接口不得信任客户端直接传入的 `tenant_id` 作为访问授权依据。
3. 租户端请求的租户范围从认证上下文推导。
4. 超级管理员跨租户访问必须走平台级权限校验并记录审计日志。
5. pgvector 检索必须同时按 `tenant_id` 和 `chatbot_id` 过滤。
6. 文件存储路径必须按租户隔离，且原始文件不得通过公开路径直接访问。

## 8. 模块关系总览

### 8.1 主要依赖链路

1. `tenant-admin` → 认证与权限 → Chatbot 管理 → 知识库/规则问答/渠道部署。
2. `super-admin` → 认证与权限 → 租户管理/套餐额度/模型供应商/审计。
3. `chatbot-widget`、`chat-page` → 渠道部署校验 → 对话编排 → 规则问答 → 知识库 → 模型调用。
4. 对话编排 → 会话记录 → 统计报表。
5. 套餐额度 → Chatbot 管理、知识库、对话编排、模型调用。
6. 审计日志 ← 认证、租户管理、套餐额度、模型供应商、会话数据导出删除。

### 8.2 模块关系矩阵

| 模块 | 主要上游 | 主要下游 |
| --- | --- | --- |

## 9. 安全与非功能设计

### 9.1 安全设计

1. 后台接口必须鉴权，按角色授权。
2. 密码使用安全哈希算法存储。
3. 租户数据通过 `tenant_id` 和认证上下文严格隔离。
4. 插件入口校验 chatbot 状态和域名白名单。
5. 模型供应商 API 密钥加密保存或通过安全配置管理。
6. 敏感信息默认脱敏展示，仅授权角色可查看完整值。
7. 文件上传限制类型和大小。
8. 网页抓取限制频率和超时时间。
9. 导出、删除和超级管理员跨租户访问必须记录审计日志。

### 9.2 性能设计

1. 聊天接口需在 3 秒内返回首个结果或处理中状态。
2. 规则问答匹配目标 500 毫秒内完成。
3. 知识库检索目标 1 秒内完成。
4. 后台列表页目标 2 秒内返回。
5. 文件解析、网页抓取和向量生成异步处理。

### 9.3 可用性设计

1. 模型供应商调用失败时返回友好错误或兜底话术。
2. 文件解析失败时展示明确失败原因。
3. 套餐额度不足时展示具体限制项。
4. 关键操作进入审计链路。

### 9.4 国际化设计

1. 用户端 chatbot 支持中文和英文界面。
2. 租户端和超级管理员端支持中文和英文界面。
3. FAQ 和知识库内容支持中文和英文。
4. chatbot 默认回复语言由行为策略配置决定。
